# 新案例入库流程(evolution)

> 用途:把用户新发的提示词案例,按固定流程拆解、判定冲突、写进对应文件。
> 本文件管**增量**(新案例怎么进来);`case-studies.md` 管**存量**(已入库案例与取舍记录)。
>
> ⚠️ 本文件是据「六步流程 + 冲突裁决顺序」重建的草稿版。实际流程若有出入,以你的版本为准。

---

## 一、触发条件

用户发来提示词案例(单条或多条),无论是否明说"入库",只要满足任一条就走本流程:

- 提供了完整的提示词正文
- 要求"看看这个怎么样 / 有什么可学的"
- 同一题材有多条对比

**不走本流程**:用户只是要写一条新提示词(那是主流程),或只是讨论某个技法(直接答)。

---

## 二、六步流程

### Step 1 · 读原文,剥离越界内容

逐条读,先做一次内容分级:

| 情况 | 处理 |
|---|---|
| 含露骨内容(裸露、性行为、身体部位特写) | **只萃取技法,不复刻描写**;在入库记录里注明"已剥离" |
| 含未成年 / 校服 / 幼态设定 | 整条剔除,不入库 |
| 含偷窥视角(裙底、偷拍) | 剔除该句,保留其余 |
| 正常时装/生活写真 | 完整入库 |

### Step 2 · 拆技法

按五个维度拆,每条案例最多提炼 3 条新东西:

| 维度 | 问什么 |
|---|---|
| **结构** | 用什么分段方式?顺序有什么讲究? |
| **词库** | 有没有我们没见过的写法(面料、光、姿势、配饰) |
| **叙事** | 用什么"瞬间"或"拍摄者关系"让画面可信 |
| **锁定** | 怎么固定关键物件、肢体、构图 |
| **反 AI** | 有没有新的去 AI 感手段 |

**没提炼出新东西的案例,不单独入库**,只在 case-studies 里记一行"与本库重合"。

### Step 3 · 归类到已有类别

| 提炼出的东西 | 写进哪 |
|---|---|
| 服装/面料/剪裁 | `garments.md` / `fabrics-colors.md` |
| 首饰/配饰/鞋 | `jewelry-accessories.md` |
| 姿势/机位/人体结构 | `pose-and-anatomy.md` |
| 光线/肤质/去AI感 | `anti-ai-realism.md` |
| 分段结构/模板/负面词 | `prompt-templates.md` |
| 品牌语言 | `brands.md`(女装)/ `menswear.md`(男装) |
| 案例本身与取舍 | `case-studies.md` |

**都不合适时**:新建一节,不要硬塞进不相关的文件。

### Step 4 · 冲突检测

新技法入库前,先跟现有规则逐条对一遍。**每条冲突都要显式列出**,不能默默覆盖。

常见冲突类型:

1. **正反说法冲突**——如"负面词折进正向" vs "负面词不进正文"
2. **参数冲突**——如"A 说 50 步" vs "B 说 8 步"
3. **风格冲突**——如"要走厚涂" vs "要走写实"(这种不算冲突,是双模式)
4. **适用条件冲突**——看起来矛盾,其实各管一种场景(最常见)

### Step 5 · 裁决

按下面的优先级判定,高优先级胜出。**同级冲突不覆盖,并列保留并注明适用条件。**

### Step 6 · 写入并留痕

1. 改对应文件
2. 在 `case-studies.md` 加一行记录:案例来源 / 提炼了什么 / 是否有冲突
3. 若这条新规则推翻了旧规则,**在旧规则处加一句"已废止(见 XX 节)"**,不要直接删——后人需要知道为什么改

---

## 三、冲突裁决顺序(优先级从高到低)

| 级 | 依据 | 说明 |
|---|---|---|
| **1** | **本机实测** | 在我们这套环境里跑出来的数据,优先级最高。要注明模型、分辨率、采样器、种子 |
| **2** | **模型官方文档/官方模板** | 官方给的结构和参数,没实测过也先信 |
| **3** | **多来源交叉验证** | 两条以上独立案例都这么说 |
| **4** | **单一来源的技法** | 只有一条案例支撑,可以采纳但要标注"单例" |
| **5** | **个人偏好** | 个人审美/地域偏好,只做**可选开关**,不进默认规则 |

**同级且互相矛盾时**:
- 若各自有明确适用条件 → **并列保留**,在文中写清"什么情况下用哪个"
- 若适用条件不明 → **不采纳新说法**,保持现状,并在记录里注明"待验证"

**特别规则**:
- **实测推翻官方**时,按实测来,但要在文中注明"官方写的是 X,实测是 Y"
- **个人偏好冒充通用规则**时,降级为可选开关(如肤色偏好、地域角色卡)

---

## 四、入库记录的固定格式

每条新案例在 `case-studies.md` 末尾加一行:

```
| 编号 | 来源 | 维度 | 提炼 | 冲突 | 备注 |
| T28 | 用户提供 | 光线 | 写"灯罩压低、光只往一个方向打" | 无 | — |
| T29 | 用户提供 | 结构 | 七段式,比八段式少"身材/镜头" | 与 F 八段式 | 并列,七段用于无身材要求的题材 |
```

**字段说明**:
- **维度**:结构 / 词库 / 叙事 / 锁定 / 反AI
- **冲突**:无 / 有(写冲突对象)
- **备注**:裁决结果或适用条件

---

## 五、维护约定

1. **只增不删**:被推翻的规则标"已废止",保留原文
2. **不整包覆盖**:任何外部版本进来,先 diff 再合并,避免把已有修正冲掉
3. **每次改动留时间戳**:在文末记一行版本说明
4. **个人偏好永远标"可选"**:肤色、地域、具体品牌倾向
